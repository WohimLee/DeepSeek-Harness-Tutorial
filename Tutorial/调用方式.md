

## DeepSeek

数完包清单了。**对外可被其它 agent 调用的入口有 7 条**，加上 2 条扩展点共 9 种；另有 3 条是反向（我去调别人）的，不算在内。

## 入站：其它 agent 驱动我

| # | 入口 | 传输 | 对应包（bundle 内，均 `0.2.0-rc.2`） |
|---|---|---|---|
| 1 | **ACP 服务器** | stdio JSON-RPC | `dsh-acp` + `dsh-acp-app` |
| 2 | **SDK JSON-RPC 服务器** | stdio 按换行分帧 | `dsh-sdk-jsonrpc-server` + `dsh-sdk-app` / `dsh-sdk-minimal` / `dsh-sdk-protocol` |
| 3 | **一次性任务** | 进程参数 + stdout / `--json` 行事件 | `dsh-headless` |
| 4 | **HTTP + WebSocket**（我当前就是这条） | loopback `127.0.0.1:19387` | `dsh-host-webserver` + `dsh-api-gateway` + `dsh-api-*-controller` |
| 5 | **Webhook 规则** | 受信外部事件 → 新建根会话 | `dsh-webhook` + `dsh-webhook-github` |
| 6 | **Subagent** | 进程内 fork / spawn，或进程外 ACP | `dsh-subagent*`、`dsh-tool-subagent*` |
| 7 | **插件扩展点** | Cordis 插件 / Typert RPC | `dsh-plugin-manager`、`dsh-typert-*`、`dsh-package-manifest` |

## 对应 5 个可直接启动的 profile

bundle 清单里能起应用 profile 的组合包有：`dsh-base`、`dsh-desktop-host`、`dsh-web-app`、`dsh-headless`、`dsh-sdk-app`、`dsh-acp-app`。文档里出现的启动方式：

```sh
dsh --profile acp        # 入口 1
dsh --profile sdk        # 入口 2
dsh --profile headless "run the tests"   # 入口 3
dsh --profile web        # 入口 4
```

（bundle 里还提到 `tui` 字串，但我没找到对应应用组合包，所以不列为已确认入口。）

## 你现在实际能用哪几条

这点必须说清楚，否则容易误判：

- **入口 4 正在运行**：就是你现在这个 GUI，监听 `127.0.0.1:19387`，profile 里 `networkExposure: loopback`。
- **入口 1/2/3 只是随包分发，未激活**：当前 `desktop` profile 的 bundles 只有 `dsh-base` + `dsh-web-app`，要另起进程用上表命令。启动器是 `/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh`（我没执行它，只做了 shell 语法检查）。
- **入口 7 的边界**：这是扩展点不是协议，第三方插件往 stdout 写东西会破坏 ACP/SDK 的帧纯净性，官方文档明确把这一点列为已知限制。

另外，入口 2 有官方配套客户端：TypeScript 的 `dsh-sdk-client` 和上游仓库的 **Python SDK**，两者都复现同一份 wire format。
